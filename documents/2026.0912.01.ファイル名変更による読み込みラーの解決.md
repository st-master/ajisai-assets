# ファイル名変更による読み込みエラーの解決
## 問１：
文書名をすべて小文字の2026.09から始まる文字列に変えました…  
すると…  
文書の読み込みに失敗しました…

---
## 解１：
ファイル名（リポジトリ上の実際のパス）と、コード側（またはURLパラメータ）で指定しているパスの**大文字・小文字の表記不一致**が原因です。

GitHub Pagesのウェブサーバーは**大文字・小文字を厳密に区別**（Case-sensitive）します。

**主なチェックポイントと修正手順**

1. **URL（コード側）の設定確認**
現在開かれているURLの末尾を見ると、日本語のファイル名部分がエンコードされた状態になっています。
```text
file=2026.0912.00.%E3%81%93%E3%81%AE%E3%82%B5%E3%82%A4%E3%83%88%E3%81%AE%E7%9B%AE%E7%9A%84%E3%82%92%E8%A6%81%E7%B4%84.md

```


もし実際のファイル名を小文字アルファベットに変更した場合は、呼び出し側の `file=` パラメータやJavaScript内のパス設定も新しいファイル名に更新してください。
2. **拡張子（`.md` や `.MD`）の表記確認**
ファイル名を小文字に変更した際、拡張子部分まで小文字（例: `.md`）になっているかご確認ください。
3. **リポジトリへの反映（Commit & Push）**
Gitの設定によっては、大文字・小文字のみの変更が追跡されない場合があります。確実に反映させるため、以下の手順をお試しください。
```bash
# 一度別の名前に変更してから戻すか、git mv を使用する
git mv OldFileName.md tempname.md
git mv tempname.md newfilename.md
git commit -m "Fix file name casing"
git push

```
ファイル名とプログラム/URL側のパス指定を完全に一致させることで、正常に読み込めるようになります。

## 問２：
Live‐Serverでは…文書表示されます…
GitHub側に問題あると思います…
nojikill.git？…というような空白のファイルをどこかに置けばよかった気もするのですが…

---
## 解２：
それ（`nojikill.git`）は、**`.nojekyll`**（ドット・ノー・ジキル）という名前の空ファイルのことですね！

GitHub Pagesはデフォルトで**Jekyll（ジキル）**という静的サイト生成ツールが動いており、**「`_`（アンダースコア）から始まるファイルやディレクトリ」を無視・無視排除する仕組み**になっています。

---

### **原因と対策**

* **原因**: JavaScriptやHTML、あるいは画像・文書の配置フォルダや設定で Jekyll の処理に引っかかり、一部のファイルがビルド時にスキップされて「読み込み失敗」になっている可能性が高いです。（LocalのLive ServerはJekyllが動かないため正常に表示されます）
* **解決策**: リポジトリのルート直下（一番上の階層）に **`.nojekyll`** という名前で空のファイルを作成し、GitHubにプッシュしてください。

---

### **`.nojekyll` ファイルの作成手順**

1. **VS Code または ターミナルで作成**
リポジトリの直下（一番上のフォルダ）に、ファイル名 `.nojekyll`（先頭にドットが必要）で空ファイルを作成します。
* **ターミナル（Mac/Linux/Git Bash等）の場合:**
```bash
touch .nojekyll

```


* **Windowsコマンドプロンプトの場合:**
```cmd
type nul > .nojekyll

```




2. **GitHubへ反映**
```bash
git add .nojekyll
git commit -m "Add .nojekyll to disable Jekyll"
git push

```
